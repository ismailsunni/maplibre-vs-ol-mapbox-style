Reference: how the label background is done in each renderer

      

        The Mapbox/MapLibre style spec has no
        text-background property, so a filled box behind a label is
        achieved differently in each renderer. The boxes above look the same, but the
        two paths are not — recorded here for the future migration to native MapLibre.
      


      

        

          
            

              
              Native MapLibre GL JS
              OpenLayers + ol-mapbox-style
            

          
          
            

              Box mechanism
              icon-image + icon-text-fit: "both"
              OpenLayers' native Text.backgroundFill
            

            

              Where the box comes from
              a sprite image, referenced by the style's sprite URL
              metadata["ol:text-background"], read by a post-apply() helper
            

            

              Extra app code?
              None — pure style (spec-native)
              Yes — a small setStyle override after apply()
            

            

              Box colour source
              the sprite PNG's pixels
              the metadata fill
            

            

              Corner shape
              rectangle (square sprite)
              rectangle (no border radius)
            

          
        

      


      
To reproduce this styling

      
    
        
  • 
          Native MapLibre — the clean, maintainer-recommended way
          (mapbox-gl-js #5381): add a sprite to the style with a 9-slice box icon, then on the
          symbol layer set icon-image,
          icon-text-fit: "both" and icon-text-fit-padding. No
          JavaScript — the box colour lives in the sprite image.
        
    • 
        
  • 
          ol-mapbox-style — it implements neither
          icon-text-fit nor a text background, so after
          apply() / stylefunction() wrap the layer's style
          function and set backgroundFill / backgroundStroke /
          padding on each Text style, reading the colour and
          padding from metadata["ol:text-background"].
        
    • 
      


      

        For the migration to native MapLibre: the OpenLayers
        backgroundFill workaround is no longer needed — the
        icon-image + icon-text-fit + sprite
        approach is spec-native and requires no hacky renderer code. The
        workaround lives in OpenLayers, not in MapLibre.
